# wheremycv — Requirements (Draft v0.2)

> เว็บช่วยจำว่าส่ง CV/Resume ไปที่ไหน เมื่อไหร่ ใครตอบกลับแล้วบ้าง และมีนัดสัมภาษณ์วันไหน
> ใช้ได้ทั้งบนเว็บและใน LINE (LIFF) พร้อมแจ้งเตือนผ่าน LINE
> **เป็นแบบ self-host:** ใครอยากใช้ให้โคลน repo ไป ใส่ key ของตัวเอง แล้ว deploy ขึ้น Cloudflare ของตัวเอง

อัปเดตล่าสุด: 2026-11-12

---

## 1. แนวคิดและขอบเขต

- **1 การติดตั้ง = 1 เจ้าของ** (ให้คนที่เจ้าของอนุญาตใช้ร่วมได้ ดูข้อ 2)
- ไม่มีระบบสมัครสมาชิกสาธารณะ ไม่ต้องมี privacy policy สำหรับคนภายนอก
- เป็นเครื่องมือช่วยจำและดูสถิติของตัวเอง ไม่มีการอัปโหลดไฟล์ CV
- เน้นใช้บนมือถือ (mobile-first) เพราะส่วนใหญ่จะเปิดผ่าน LIFF
- ภาษาไทยเป็นหลัก
- **README ต้องละเอียดพอ** ให้คนที่ไม่เคยใช้ Cloudflare หรือ LINE Developers ติดตั้งเองได้

## 2. การล็อกอิน

| # | Requirement |
|---|---|
| A1 | แอปเป็น **LINE LIFF app** และล็อกอินด้วย **LINE เท่านั้น** ไม่มีอีเมลหรือรหัสผ่าน |
| A2 | เปิดใน LINE แล้วล็อกอินอัตโนมัติ ถ้าเปิดลิงก์ LIFF (`https://liff.line.me/<LIFF_ID>`) ในเบราว์เซอร์ปกติ จะเรียก `liff.login()` และ redirect ไปล็อกอิน LINE |
| A3 | ฝั่ง client ส่ง **ID token** (`liff.getIDToken()`) ให้เซิร์ฟเวอร์ แล้วเซิร์ฟเวอร์ verify ก่อนออก session cookie (ดู S2) |
| A4 | ใช้ได้เฉพาะ LINE userId ที่อยู่ใน **allowlist** ใน env คนอื่นที่เปิดเข้ามาจะเจอหน้า "ไม่มีสิทธิ์ใช้งาน" |
| A5 | ข้อมูลแยกตาม `user_id` เผื่อเจ้าของให้แฟนหรือเพื่อนใช้ร่วมในการติดตั้งเดียวกัน |

> หน้าแรกที่ยังไม่ได้ล็อกอิน ห้ามเผยข้อมูลใดๆ ออกไป

### 2.1 ความปลอดภัย: คนที่โคลน repo ไปต้องเข้าเว็บของเจ้าของไม่ได้ (และกลับกัน)

| # | ข้อบังคับ | กันอะไร |
|---|---|---|
| S1 | **ห้ามมี secret ใดๆ อยู่ใน repo** ค่าจริงอยู่ใน `.dev.vars` (ซึ่ง gitignore ไว้) และ `wrangler secret` เท่านั้น ใน repo มีแค่ `.dev.vars.example` ที่เป็นค่าว่าง ส่วน `wrangler.jsonc` ใช้ placeholder สำหรับ `database_id`, domain และ LIFF ID | กันไม่ให้คนโคลนได้ key ของเจ้าของไปด้วย |
| S2 | **ตรวจสอบ LINE ID token ที่ฝั่งเซิร์ฟเวอร์เท่านั้น** ผ่าน `POST https://api.line.me/oauth2/v2.1/verify` โดยต้องเช็กว่า `client_id` ตรงกับ `LINE_LOGIN_CHANNEL_ID` ของเว็บนี้ **ห้ามเชื่อ userId ที่ฝั่ง client ส่งมา** (เช่นค่าจาก `liff.getProfile()`) | กันไม่ให้ใครปลอม userId หรือเอา token จาก LINE channel ของตัวเองมาใช้กับเว็บเรา |
| S3 | **Allowlist แบบ fail-closed:** ถ้า `ALLOWED_LINE_USER_IDS` ว่าง ต้อง **ไม่มีใครเข้าได้เลย** (ห้ามตีความว่าให้ทุกคนเข้าได้) และตรวจ allowlist ทุก request ไม่ใช่แค่ตอนล็อกอิน | กันกรณีลืมตั้งค่าแล้วเว็บเปิดให้ทุกคนเข้า และกันกรณีลบใครออกจาก allowlist แล้ว session เก่ายังใช้ได้ |
| S4 | **Session เซ็นด้วย `AUTH_SECRET` ที่แต่ละการติดตั้งสุ่มขึ้นเอง** เป็น cookie แบบ `HttpOnly`, `Secure`, `SameSite=Lax` และมีวันหมดอายุ แอปต้องไม่ยอมเริ่มทำงานถ้าไม่มี `AUTH_SECRET` หรือสั้นกว่า 32 ตัวอักษร | กันไม่ให้เอา cookie ของการติดตั้งอื่นมาใช้ หรือปลอม session ขึ้นมาเอง |
| S5 | **ไม่มีรหัสผ่านและไม่มีบัญชีตั้งต้น** ล็อกอินได้ทางเดียวคือ LINE ID token ที่ verify แล้ว และไม่มี "โหมด dev" ที่ข้ามการล็อกอินได้บน production | กันช่องทางล็อกอินอื่นที่ข้าม LINE ไปได้ |
| S6 | ข้อมูลอยู่ใน D1 ของบัญชี Cloudflare ของแต่ละคน และ binding เข้าถึงได้เฉพาะ Worker ในบัญชีนั้น ไม่มี API เปิดให้ภายนอกอ่านข้อมูลได้ถ้าไม่ล็อกอิน | กันไม่ให้การติดตั้งอื่นเข้ามาอ่านข้อมูลข้ามกัน |
| S7 | Endpoint ของ cron และ webhook ต้องไม่ถูกเรียกจากภายนอกได้: cron ใช้ `scheduled()` handler (ไม่มี URL ให้เรียก) และ webhook ต้องตรวจ `x-line-signature` | กันคนภายนอกสั่งยิงแจ้งเตือนเอง |
| S8 | มีการตรวจหา secret ที่หลุดเข้า git (เช่น gitleaks ใน pre-commit หรือใน CI) และมี test ครอบ S2, S3 และ S4 | กันการพลาดในอนาคต |
| S9 | **ห้ามมีโดเมนจริงหรือ URL ของเจ้าของอยู่ใน repo** ทั้งในโค้ด, `wrangler.jsonc`, README และตัวอย่าง ให้ใช้ `example.com` แทน URL จริงอ่านจาก env (`APP_URL`) และผูก custom domain ผ่าน Cloudflare dashboard เท่านั้น | กันไม่ให้ repo สาธารณะโยงไปถึงเว็บอื่นของเจ้าของ |
| S10 | **Cookie แยกจากเว็บอื่นในโดเมนเดียวกัน:** session cookie ใช้ prefix `__Host-` (บังคับว่าห้ามมี `Domain`, ต้องเป็น `Secure` และ `Path=/`) จึงใช้ได้เฉพาะ subdomain นี้ ไม่แชร์กับโดเมนหลักหรือ subdomain อื่น และแอปจะอ่านเฉพาะ cookie ของตัวเอง | กันไม่ให้เว็บอื่นในโดเมนเดียวกันอ่านหรือเขียนทับ session |
| S11 | ปิด `workers_dev` และ `preview_urls` ใน `wrangler.jsonc` ให้เข้าได้ทาง custom domain ทางเดียว | กันการเข้าผ่าน URL สำรองที่ไม่ได้ตั้งใจเปิดไว้ |

**สรุป:** ทุกการติดตั้งมี LINE channel, `AUTH_SECRET` และ D1 ของตัวเอง โค้ดเหมือนกันแต่ไม่มี key ร่วมกันเลย ต่อให้คนโคลนรู้ LINE userId ของเจ้าของ ก็ทำได้แค่ใส่ใน allowlist ของเว็บตัวเอง ไม่มีผลกับเว็บของเจ้าของ

## 4. อัปเดตความคืบหน้า (Timeline)

กดปุ่ม **"อัปเดต"** ในการ์ด แล้วกรอก:

- **วันที่** ของเหตุการณ์
- **ประเภทเหตุการณ์** ได้แก่
  - ตอบกลับแล้ว
  - นัดสัมภาษณ์ → กรอกวัน เวลา รูปแบบ (Onsite / Online) สถานที่หรือลิงก์ และรอบที่
  - สัมภาษณ์แล้ว
  - ทำแบบทดสอบ / Assignment (มีกำหนดส่ง)
  - ได้ Offer
  - ไม่ผ่าน
  - ถอนตัว
  - โน้ตทั่วไป
- **โน้ต**

**การแสดง timeline**
- เป็นเส้นแนวตั้ง **เรียงจากบนลงล่างตามเวลา** บนสุดคือ "ส่ง CV" ล่างสุดคือเหตุการณ์ล่าสุด
- แต่ละจุดมีไอคอนและสีตามประเภท แสดงวันที่ หัวข้อ และโน้ต
- **สัมภาษณ์แต่ละรอบเป็นจุดแยกกัน** เช่น "สัมภาษณ์รอบ 1", "สัมภาษณ์รอบ 2" (เลขรอบรันให้อัตโนมัติ แก้เองได้)
- นัดที่ยังมาไม่ถึงแสดงเป็นจุดแบบเส้นประ พร้อมนับถอยหลัง "อีก X วัน"

**สถานะบนการ์ด** เปลี่ยนตามเหตุการณ์ล่าสุด:
`ส่งแล้ว → ตอบกลับแล้ว → นัดสัมภาษณ์ → สัมภาษณ์แล้ว → Offer / ไม่ผ่าน / ถอนตัว`
และมีสถานะพิเศษ **"เงียบ (Ghosted)"** ตามข้อ 6

## 5. หน้าจอ

### 5.1 หน้าแรก — รายการการ์ด
- การ์ดหนึ่งใบต่อหนึ่งรายการ **หัวการ์ดคือชื่อบริษัท** บรรทัดรองคือตำแหน่ง แล้วตามด้วยสถานะ (สีตามสถานะ) วันที่ส่ง และ "ผ่านมาแล้ว X วัน"
- ด้านบนแสดง **แถบเตือน** และนัดที่ใกล้ที่สุด
- ค้นหา กรองตามสถานะ และเรียงลำดับได้
- ปุ่มลอย **"+ เพิ่ม"**

### 5.2 หน้ารายละเอียด
- ข้อมูลของรายการ พร้อม timeline
- ปุ่ม "อัปเดต", "แก้ไข" และ "ลบ"
- ในเหตุการณ์นัดสัมภาษณ์มีปุ่ม **"เพิ่มลงปฏิทิน"**

### 5.3 ปฏิทิน
- ปฏิทินรายเดือนในเว็บ ใช้แนวทางเดียวกับ `MonthCalendar` ของ jellybloom
- แสดงนัดสัมภาษณ์ กำหนดส่ง Assignment และวันที่ส่ง CV

### 5.4 สถิติ
- จำนวนที่ส่งทั้งหมด และแยกตามสถานะ
- อัตราการตอบกลับ อัตราได้สัมภาษณ์ และอัตราได้ Offer
- ระยะเวลาเฉลี่ยกว่าจะได้รับการตอบกลับ
- จำนวนที่ส่งต่อสัปดาห์/เดือน
- อัตราตอบกลับแยกตามช่องทางที่ส่ง

### 5.5 ตั้งค่า
- ตั้งจำนวนวันสำหรับการเตือน
- เปิด/ปิดการแจ้งเตือน LINE และเลือกเวลาส่งสรุปประจำวัน
- ปุ่ม "ส่งข้อความทดสอบ" เพื่อเช็กว่าตั้งค่า LINE ถูกต้อง

## 6. การเตือน

### 6.1 เงื่อนไข (ผู้ใช้ตั้งเองได้)

| เตือน | เงื่อนไข | ค่าเริ่มต้น |
|---|---|---|
| ควร Follow up | ส่งแล้ว ยังไม่มีอัปเดตเกิน N วัน | 14 วัน |
| น่าจะเงียบไปแล้ว | ไม่มีอัปเดตเกิน M วัน → เสนอให้เปลี่ยนเป็น Ghosted | 30 วัน |
| นัดใกล้ถึง | มีนัดสัมภาษณ์หรือกำหนดส่งภายใน K วัน | 1 วัน |

แต่ละรายการกด **"ไว้ทีหลัง" (snooze)** หรือปิดการเตือนได้

### 6.2 ช่องทาง

- **ในเว็บ:** แสดงเป็นแถบบนหน้าแรกและป้ายบนการ์ด คำนวณใหม่ทุกครั้งที่เปิดหน้า
- **LINE push:** ใช้ Cloudflare **Cron Trigger** รันวันละครั้ง (ค่าเริ่มต้น 08:00 เวลาไทย) แล้วส่ง**สรุปรวมเป็นข้อความเดียว** ต่อคน เช่น "วันนี้มีสัมภาษณ์ 1 นัด และมี 3 ที่ที่ส่งไปเกิน 14 วันแล้วยังไม่ตอบ" เพื่อประหยัดโควตาข้อความของแพ็กฟรี
  - ถ้าวันไหนไม่มีอะไรต้องเตือน **จะไม่ส่ง**
  - ในข้อความมีปุ่มลิงก์เปิด LIFF ไปหน้าที่เกี่ยวข้อง
  - ข้อความเป็น Flex Message

## 8. Tech Stack

| ส่วน | เทคโนโลยี |
|---|---|
| Frontend + Backend | **Next.js** (App Router) |
| Hosting | **Cloudflare Workers** ผ่าน `@opennextjs/cloudflare` deploy อัตโนมัติด้วย Workers Builds เมื่อ push เข้า `main` |
| Domain | **Custom Domain** ของ Worker เป็น subdomain ของโดเมนที่ผู้ติดตั้งมีอยู่ (เช่น `wheremycv.example.com`) ตั้งใน dashboard ไม่ใส่ใน repo (S9) |
| Database | **Cloudflare D1** + Drizzle ORM (มี migration ให้รันใน README) |
| Cron | Cloudflare Cron Triggers (ต้องห่อ worker ของ OpenNext ด้วย custom entry ที่มี `scheduled()` handler) |
| LINE | LINE Login channel + LIFF + Messaging API channel |

## 9. สิ่งที่ผู้ติดตั้งต้องเตรียม (ต้องเขียนไว้ใน README)

1. บัญชี Cloudflare (ฟรี) และ Node.js
2. **LINE Developers:** สร้าง **Provider เดียวกัน** แล้วสร้างในนั้น:
   - **LINE Login channel** → สร้าง LIFF app
   - **Messaging API channel** (คือ LINE OA ของตัวเอง)
   - ⚠️ ทั้งสองต้องอยู่ใน provider เดียวกัน เพราะ LINE userId ผูกกับ provider ถ้าคนละ provider จะส่ง push หาตัวเองไม่ได้
   - ตั้ง "Linked OA" ใน Login channel และใช้ `bot_prompt=aggressive` ให้เพิ่ม OA เป็นเพื่อนตอนล็อกอิน
3. แอดเพื่อน LINE OA ของตัวเอง
4. ใส่ env และ secret แล้ว deploy

### Environment variables (ร่าง)

| ตัวแปร | ใช้ทำอะไร |
|---|---|
| `APP_URL` | URL ของเว็บหลัง deploy เช่น `https://wheremycv.example.com` (ตั้งใน dashboard ไม่ commit) |
| `AUTH_SECRET` | ใช้เซ็น session (สุ่มเอง) |
| `ALLOWED_LINE_USER_IDS` | LINE userId ที่อนุญาต คั่นด้วย `,` |
| `LINE_LOGIN_CHANNEL_ID` / `LINE_LOGIN_CHANNEL_SECRET` | LINE Login |
| `NEXT_PUBLIC_LIFF_ID` | LIFF app |
| `LINE_MESSAGING_CHANNEL_ACCESS_TOKEN` | ส่ง push message |
| `LINE_MESSAGING_CHANNEL_SECRET` | ตรวจลายเซ็น webhook (ถ้าใช้) |
| `TZ` | ค่าเริ่มต้น `Asia/Bangkok` |

> ค่าที่เป็นความลับใส่ด้วย `wrangler secret put` ส่วนตอนรันในเครื่องใช้ `.dev.vars` (ต้องมีใน `.gitignore` และมี `.dev.vars.example` ให้ก๊อปไปใช้)
> README ต้องมีคำสั่งสุ่ม `AUTH_SECRET` ให้ (เช่น `openssl rand -base64 32`) และเตือนว่า **ห้าม commit `.dev.vars`** หรือก๊อป secret ไปให้คนอื่น
> ถ้ายังไม่รู้ LINE userId ของตัวเอง ให้มีหน้า/คำสั่งช่วยแสดง userId หลังล็อกอินครั้งแรก

## 10. Non-functional

- Responsive และ mobile-first ใช้ใน LIFF ได้ลื่น
- ทุก query กรองด้วย `user_id` และตรวจ allowlist ทุก request
- เวลาอิงโซน `Asia/Bangkok`
- ใช้งานได้ภายใน free tier ของ Cloudflare และ LINE OA
- ส่งออกข้อมูลเป็น CSV (เฟส 2)
